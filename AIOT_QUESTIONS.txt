(핵심) Q01. 강의자료의 사물인터넷 아키텍처에서 아래 계층에서 위 계층으로 올라가는 순서를 올바르게 나열한 것은?
(서비스·플랫폼·네트워크·디바이스의 4계층을 기준으로 한다.)

1. 네트워크 → 디바이스 → 서비스 → 플랫폼
2. 디바이스 → 네트워크 → 플랫폼 → 서비스
3. 서비스 → 네트워크 → 디바이스 → 플랫폼
4. 디바이스 → 플랫폼 → 네트워크 → 서비스

정답: 2번 — 디바이스 → 네트워크 → 플랫폼 → 서비스

1번 해설: 디바이스와 네트워크, 플랫폼과 서비스의 위치가 모두 뒤바뀌었습니다.
2번 해설: 센서·액추에이터가 있는 디바이스 위에 네트워크, 공통 플랫폼, 응용 서비스가 배치됩니다. 보안은 한 계층에만 한정된 항목이 아니라 여러 계층에 걸쳐 고려됩니다.
3번 해설: 서비스는 도식의 상위 응용 계층이며 디바이스가 최하위에 놓입니다.
4번 해설: 강의 도식에서는 디바이스와 플랫폼 사이에 네트워크가 위치합니다.

(핵심) Q02. DHT11을 초기화한 뒤 습도와 섭씨 온도를 읽으려 한다. (A)~(C)에 순서대로 들어갈 것은?

#include <DHT.h>
DHT dht(7, DHT11);

void setup() {
  dht.(A)();
}
void loop() {
  delay(2000);
  float h = dht.(B)();
  float t = dht.(C)();
}

1. init / readHumidity / readTemperature
2. begin / readTemperature / readHumidity
3. begin / analogRead / digitalRead
4. begin / readHumidity / readTemperature

정답: 4번 — begin / readHumidity / readTemperature

1번 해설: 제시한 DHT 객체의 초기화 함수는 init()이 아니라 begin()입니다.
2번 해설: 온도와 습도를 읽는 함수의 순서가 바뀌었습니다.
3번 해설: 이 예제의 DHT 객체는 readHumidity(), readTemperature()를 사용합니다. Arduino의 일반 입출력 함수를 DHT 멤버처럼 호출하지 않습니다.
4번 해설: begin()으로 초기화하고 readHumidity()로 습도, readTemperature()로 섭씨 온도를 읽습니다. 예제는 2,000ms 간격을 두며 setup()은 초기화, loop()는 반복 측정을 담당합니다.

(핵심) Q03. 온도와 습도 중 하나라도 읽기에 실패하면 현재 loop() 실행을 끝내고 싶다. (A), (B)에 들어갈 것은?

float h = dht.readHumidity();
float t = dht.readTemperature();
if ((A)(h) || (A)(t)) {
  Serial.println("Sensor error");
  (B);
}
// 이 아래에서 정상 측정값을 이용한다.

1. isnan / return
2. isnan / break
3. isfinite / return
4. isnan / continue

정답: 1번 — isnan / return

1번 해설: isnan()은 값이 NaN인지 검사합니다. ||로 연결하면 하나라도 NaN일 때 return으로 이번 loop()를 빠져나옵니다. NaN 여부는 int로 변환하기 전의 float 값에서 확인해야 합니다.
2번 해설: break는 반복문 또는 switch를 빠져나가는 문장입니다. 제시된 if 안에는 break가 빠져나갈 반복문이나 switch가 없습니다.
3번 해설: isfinite는 정상적인 유한값일 때 참입니다. 읽기 실패를 검사하려는 이 조건과 반대 방향입니다.
4번 해설: continue는 for·while 등의 다음 반복으로 이동하는 문장입니다. loop라는 함수 이름 자체가 반복문을 뜻하지는 않습니다.

(핵심) Q04. LCD 1602에 I2C 컨버터를 사용했을 때의 배선과 통신 설명으로 옳은 것은?

1. SDA와 SCL은 각각 8비트를 동시에 보내는 병렬 데이터선이다.
2. SDA와 SCL은 모두 전원선이며 실제 데이터는 GND 한 선으로 전송한다.
3. SDA는 데이터선, SCL은 클럭선이며 전원·GND 외에 신호선 2개로 통신한다.
4. SDA는 클럭선, SCL은 데이터선이며 전원·GND 외에 신호선 2개로 통신한다.

정답: 3번 — SDA는 데이터선, SCL은 클럭선이며 전원·GND 외에 신호선 2개로 통신한다.

1번 해설: I2C는 직렬 통신이며 비트를 순차적으로 전송합니다.
2번 해설: SDA와 SCL은 신호선입니다. GND는 신호 전압의 기준이지 별도의 데이터선이 아닙니다.
3번 해설: I2C는 SDA와 SCL을 사용하는 동기식 직렬 통신입니다. LCD 모듈을 연결할 때는 이 두 신호선 외에 VCC와 GND도 필요하므로 보통 총 4선을 연결합니다.
4번 해설: SDA와 SCL의 역할이 뒤바뀌었습니다.

(핵심) Q06. LCD 예제의 주소 리터럴 0x27과 같은 값을 나타내는 조합은?
(각 항목의 순서는 10진수 / 2진수 리터럴 / 8진수 리터럴이다.)

1. 47 / 0b00101111 / 057
2. 27 / 0b00011011 / 033
3. 32 / 0b00100000 / 040
4. 39 / 0b00100111 / 047

정답: 4번 — 39 / 0b00100111 / 047

1번 해설: 이 조합은 0x2F에 해당합니다. 047이라는 8진수 표기를 10진수 47로 읽으면 안 됩니다.
2번 해설: 이 조합은 10진수 27이며 16진수로는 0x1B입니다.
3번 해설: 이 조합은 0x20에 해당하며 0x27보다 7 작습니다.
4번 해설: 0x27은 2×16+7=39입니다. 이 값은 2진수 00100111, 8진수 47이며 C/C++의 8진수 리터럴은 앞에 0을 붙인 047입니다.

(핵심) Q07. 강의에서 다룬 7비트 주소 방식의 I2C 통신에 대한 설명으로 옳은 것은?

1. 장치 주소 7비트와 R/W 비트 1비트를 구분하며, 수신 측은 9번째 클럭에서 SDA를 LOW로 내려 ACK를 보낼 수 있다.
2. 동일 버스의 장치는 모두 같은 주소를 사용해야 개별 선택이 가능하다.
3. 장치 주소 8비트만 전송하고 읽기/쓰기 구분 비트는 사용하지 않는다.
4. ACK는 정상 수신을 알리기 위해 수신 측이 SDA를 HIGH로 유지하는 응답이다.

정답: 1번 — 장치 주소 7비트와 R/W 비트 1비트를 구분하며, 수신 측은 9번째 클럭에서 SDA를 LOW로 내려 ACK를 보낼 수 있다.

1번 해설: 7비트 장치 주소와 1비트 읽기/쓰기 구분이 주소 전송 바이트를 구성합니다. 8비트를 전송한 뒤의 ACK는 수신 측이 SDA를 LOW로 만들어 응답하는 방식입니다.
2번 해설: 기본적으로 서로 다른 장치는 주소로 구분합니다. 같은 버스에서 주소가 충돌하면 개별 선택이 어려워집니다.
3번 해설: 문제에서 지정한 7비트 주소 방식은 주소 7비트와 R/W 1비트를 구분합니다.
4번 해설: LOW가 ACK이며 HIGH로 유지되는 응답은 NACK입니다. NACK는 읽기 종료를 알리는 상황에도 쓰이므로 항상 고장만을 뜻하지는 않습니다.

1번 해설: 이 선언은 디스플레이 객체의 주소와 크기를 설정합니다. 센서 측정값이나 시리얼 속도와는 무관합니다.

1. lcd.blink() → 커서 위치에 깜빡임 표시를 활성화한다.

4. lcd.noDisplay() → 저장된 문자 내용을 모두 삭제한다.

(핵심) Q11. 센서 입력을 계속 확인하면서 LED도 일정 간격으로 깜빡이게 하려 한다. 긴 delay() 대신 millis()로 경과 시간을 검사하는 주된 이유는?

1. 대기 시간 동안에도 loop()의 다른 코드를 실행할 기회를 주기 위해서이다.
2. millis()를 호출하면 별도의 CPU가 자동으로 하나 생성되기 때문이다.
3. millis()는 시간을 초 단위 문자열로 반환하므로 숫자 연산이 필요 없기 때문이다.
4. delay()를 사용하면 보드의 전원 공급 자체가 중단되기 때문이다.

정답: 1번 — 대기 시간 동안에도 loop()의 다른 코드를 실행할 기회를 주기 위해서이다.

1번 해설: millis() 값을 비교하는 방식은 긴 delay()로 흐름을 멈추지 않고 다른 작업을 번갈아 처리하게 합니다. 다만 pulseIn() 같은 대기 함수가 남아 있다면 전체 프로그램이 완전히 비차단식이라고 단정할 수는 없습니다.
2번 해설: millis()는 경과 시간을 알려 주는 함수이며 CPU나 실행 스레드를 생성하지 않습니다.
3번 해설: millis()는 밀리초 단위의 정수값을 반환하며 차이를 계산해 주기를 검사합니다.
4번 해설: delay()는 일반적인 프로그램 흐름을 잠시 대기시키는 함수이지 전원 차단 명령이 아닙니다.

(핵심) Q12. Arduino UNO R3에서 1초마다 LED 상태를 반전하려 한다. (A)~(C)에 순서대로 들어갈 것은?

(A) previous = 0;
bool ledState = false;

void loop() {
  unsigned long now = millis();
  if ((B) >= 1000UL) {
    previous = (C);
    ledState = !ledState;
    digitalWrite(13, ledState);
  }
}
// setup()에서 13번 핀을 OUTPUT으로 설정했다고 가정한다.

1. int / now - previous / now
2. unsigned long / now + previous / now
3. unsigned long / now - previous / now
4. unsigned long / now - previous / 0

정답: 3번 — unsigned long / now - previous / now

1번 해설: UNO R3의 int는 이 용도의 누적 밀리초를 저장하기에 범위가 작습니다. unsigned long으로 두어야 합니다.
2번 해설: 두 시각을 더하면 경과 시간이 되지 않습니다.
